# NADIR: этап 7.5

Один исполняемый проект, разделённый по ответственности.

| Файл | Ответственность |
| --- | --- |
| Program.cs | Точка входа, владение приложением |
| Application/NadirApp.cs | Окно, события, координация кадра и завершение |
| Graphics/GraphicsContext.cs | OpenGL, Skia GPU context, framebuffer, поверхность и Flush |
| Rendering/SceneRenderer.cs | Порядок рисования сцены |
| Rendering/FpsOverlay.cs | Текст FPS, владение шрифтом и кистью |
| Diagnostics/FpsCounter.cs | Расчёт FPS, без зависимости от графики |

## Жизненный цикл

1. Program создаёт NadirApp и вызывает Run ровно один раз.
2. Load создаёт графические ресурсы и renderer.
3. Render обновляет счётчик, рисует сцену и вызывает Flush.
4. Closing освобождает графические ресурсы до уничтожения контекста окна.
5. finally в Run обеспечивает очистку при ошибке, включая частичную инициализацию.
6. Dispose приложения освобождает окно. Повторная очистка графического контекста безопасна.

Все операции с окном, графикой и освобождением выполняются на потоке окна.
Canvas заимствуется на один кадр, не сохраняется и не освобождается renderer.
SwapBuffers остаётся обязанностью стандартного цикла Silk.NET.

## Следующий этап

Обработка FramebufferResize: освобождение Surface перед RenderTarget,
пересоздание их по размеру framebuffer, сохранение GRContext.
При нулевом размере framebuffer нужно приостановить рисование до восстановления.
В этой версии resize ещё не реализован; начальный размер должен быть положительным.
